| 2026-11-27 | The four older PDF/X levels are named `x1a-2001`, `x3-2002`, `x1a-2003`, `x3-2003` (in `checks.toml`, `--pdfx`, `Profile.pdfx_level` and `_core.verify`), hyphenated so the year reads apart from the level; the plan's `x1a2001` was a sketch. Without `--pdfx`, a file whose identification (XMP `pdfxid:GTS_PDFXVersion`, else Info `/GTS_PDFXVersion` with `/GTS_PDFXConformance`) claims one of the four is verified at it; any other file at PDF/X-4 as before, so no X-4 or X-5 result changes (an X-4p or X-5 claim is not detected: those levels keep needing `--pdfx`). | 2026-11-27 | PDF/X-1a and X-3, the owner's answers to the phase-0 stop: transparency at X-1a:2001 and X-3:2002 is an error (L-Q3), citing clause 5 and the data-structure clause, and 15930-3 Annex D at X-3:2002; what counts is Annex D.2's keys (ExtGState `BM`, `CA`, `ca`, `SMask`, image `SMask`), and form groups alone are not judged at those two levels. | 2026-11-27 | A dictionary of 16 or more entries keeps a key-to-position map beside its ordered entries, so `Dict::get` no longer scans. Its entries become private: only `Dict`'s methods (`push`, `retain`, `from_entries`, the parser's insert) change them, and each keeps the map in step. A corpus file with a 38,037-entry `/ColorSpace` and 51,000 inline images naming its entries went from 86 to 3 seconds | Progress file, "Speed"; architecture note, dictionaries |
| 2026-11-27 | A `Document` keeps the streams it has decoded, by object number, up to 256 MiB of decoded data (past that a stream is decoded afresh on each request; a stream that cannot be decoded is remembered too). The lock is not held while decoding, so a stream needing itself cannot deadlock. Profiling showed the slow corpus files re-inflating the same ICC profile at each colour-space use, once per check that walks the pages; one walk per file stays undone. This revises the architecture note's "decoded stream data is not cached" | Progress file, "Speed"; architecture note, caches |
| 2026-11-27 | "Migrate the Python tests" (phase 10) means: a check's logic is tested in Rust; the Python suite tests the Python surface (API, commands, `layout`, `texlog`, `extract`'s assembly) and keeps its end-to-end tests of the checks through the core, on PDFs built with pikepdf. Tests of deleted Python modules went with them (slice F); the helper is `core_findings`. No passing end-to-end test is deleted for overlapping a Rust one: they test the Python path too | Plan, task 10 |
| 2026-11-27 | pikepdf and Pillow leave the runtime dependencies (they stay as development dependencies, for the tests that build PDFs and read images). | 2026-11-27 | `extract`'s vector artwork: the core reads every painted path as the Python collector did (state operators by kind, `ExtGState`s by object, forms 12 deep, a form without `/Resources` reading the page's) and writes each piece with our writer, numbers as pikepdf writes them (`1`, not `1.0`) and colours in words as the content wrote them; the grouping heuristics stay in Python, which asks the core for the pieces by shape and text-run index. | 2026-11-26 | `extract` writes images by rules of our own, which keep the module's promise that images come out as stored: JPEG, JPEG 2000 and CCITT data are copied (`.jpg`, `.jp2`, `.tif` with pikepdf's TIFF header) whatever their masks, and a soft mask is a file of its own (`.mask.png`, `.mask.jpg`, ...), never composited into the image as pikepdf did. Lab, `Separation` and `DeviceN` images are listed as failures, as pikepdf failed on them. pikepdf's bug-compatible choices (a DCT `/ColorTransform` read from the first filter, alpha from masks clipped or resized bicubically) are not copied | Plan, task 9; image parity run |
| 2026-11-26 | `preview` renders with `hayro` (behind the crate's `preview` feature, which the Python module turns on) from the file as `hayro` reads it, leniently, never through the core's reader: a picture judges nothing, and a damaged file still gets one. Each page's MediaBox is rendered through our own transform, so the size and guide positions are Ghostscript's; `hayro` clips content to the CropBox. The guides are a small PDF in device pixels rendered over the page without anti-aliasing, so their colours are exact. A panic inside `hayro` is caught and reported for its page. `--gs` and `--timeout` stay on `preview` and `extract`, hidden, since config files reject unknown keys | Plan, task 9 |

| 2026-11-26 | The writer (phase 9) copies streams as the file holds them and re-serialises values (hex strings, names with `#xx` escapes, reals as the shortest text that reads back, never an exponent). ## Positioning

From comparing with Kura on 2026-11-07, recorded in the note. Kura converts, repairs and covers far more standards. proof-pdf should
not race it on breadth. It is the independent check you run on any file, including one Kura produced:

- It never repairs, so it reports defects a converter fixes silently.
- PDF/A is veraPDF's verdict, not ours.
- Total ink is measured from a CMYK render, not read from object colours.
- A check that cannot run fails; it is never reported as a pass.
- Every refusal says what is wrong and where.

- Bleed along a die line: ink must cover a band outside a cutting contour, not just past the trim box. Packaging only.
